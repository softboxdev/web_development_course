## Краткие теоретические сведения

### Что такое ER-диаграмма?

**ER-диаграмма** (Entity-Relationship diagram, диаграмма «сущность — связь») — это графическое представление структуры базы данных, которое показывает:
- **сущности** (таблицы) — объекты предметной области;
- **атрибуты** (поля) — характеристики сущностей;
- **связи** — отношения между сущностями.

### Основные понятия

| Понятие | Определение | Пример |
|---------|-------------|--------|
| **Сущность** | Объект предметной области, о котором хранятся данные | Пользователь, Заявка |
| **Атрибут** | Свойство сущности | Логин, Email, Дата |
| **Первичный ключ (PK)** | Поле, однозначно идентифицирующее запись | `id` |
| **Внешний ключ (FK)** | Поле, ссылающееся на PK другой таблицы | `id_пользователя` |
| **Связь 1:1** | Одной записи в таблице A соответствует одна запись в таблице B | Заявка — Отзыв |
| **Связь 1:M** | Одной записи в A соответствует много записей в B | Пользователь — Заявки |
| **Связь M:N** | Много записей в A соответствует много записей в B | Пользователи — Мероприятия |

### Нормализация (кратко)

- **1НФ** — все атрибуты атомарны (неделимы).
- **2НФ** — нет частичной зависимости от составного ключа.
- **3НФ** — нет транзитивных зависимостей (неключевые поля не зависят друг от друга).

> В данной работе достаточно привести базу данных к **третьей нормальной форме (3НФ)**.

## 1.4 Связи между сущностями

| Связь | Тип | Описание |
|-------|-----|----------|
| Пользователь → Заявка | **1 : M** (один-ко-многим) | Один пользователь может оставить много заявок; каждая заявка принадлежит одному пользователю |
| Мероприятие → Заявка | **1 : M** (один-ко-многим) | Одно мероприятие может быть забронировано много раз (разными пользователями); каждая заявка относится к одному мероприятию |
| Статус → Заявка | **1 : M** (один-ко-многим) | Один статус может быть присвоен многим заявкам; каждая заявка имеет один текущий статус |
| Заявка → Отзыв | **1 : 1** (один-к-одному) | Одна заявка может иметь только один отзыв; каждый отзыв относится к одной заявке |
| Пользователь ↔ Мероприятие | **M : N** (многие-ко-многим) | Реализуется через промежуточную таблицу `Заявка`: один пользователь может бронировать много мероприятий, одно мероприятие может быть забронировано многими пользователями |

## 1.6 SQL-скрипт создания базы данных (пример)

```sql
-- Создание таблицы «Пользователь»
CREATE TABLE user (
    id SERIAL PRIMARY KEY,
    login VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    phone VARCHAR(18) NOT NULL,
    role VARCHAR(20) NOT NULL DEFAULT 'user'
);

-- Создание таблицы «Мероприятие»
CREATE TABLE event (
    id SERIAL PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    date DATE NOT NULL,
    place VARCHAR(200) NOT NULL,
    description TEXT
);

-- Создание таблицы «Статус»
CREATE TABLE status (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50) UNIQUE NOT NULL
);

-- Наполнение справочника статусов
INSERT INTO status (name) VALUES
    ('Новая'),
    ('Мероприятие назначено'),
    ('Завершено');

-- Создание таблицы «Заявка»
CREATE TABLE request (
    id SERIAL PRIMARY KEY,
    user_id INT NOT NULL REFERENCES user(id),
    event_id INT NOT NULL REFERENCES event(id),
    status_id INT NOT NULL DEFAULT 1 REFERENCES status(id),
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Создание таблицы «Отзыв»
CREATE TABLE review (
    id SERIAL PRIMARY KEY,
    request_id INT UNIQUE NOT NULL REFERENCES request(id),
    text TEXT NOT NULL,
    rating INT CHECK (rating BETWEEN 1 AND 5),
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

### Этап 6. Составление SQL-скрипта (15 мин)

**Задание 6.1.** Напишите SQL-скрипт для создания всех таблиц. Используйте шаблон:

```sql
-- Создание таблицы «Пользователь»
CREATE TABLE user (
    id SERIAL PRIMARY KEY,
    login VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    phone VARCHAR(18) NOT NULL,
    role VARCHAR(20) NOT NULL DEFAULT 'user'
);

-- Создание таблицы «Мероприятие»
CREATE TABLE event (
    id SERIAL PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    date DATE NOT NULL,
    place VARCHAR(200) NOT NULL,
    description TEXT
);

-- Создание таблицы «Статус»
CREATE TABLE status (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50) UNIQUE NOT NULL
);

-- Наполнение справочника статусов
INSERT INTO status (name) VALUES
    ('Новая'),
    ('Мероприятие назначено'),
    ('Завершено');

-- Создание таблицы «Заявка»
CREATE TABLE request (
    id SERIAL PRIMARY KEY,
    user_id INT NOT NULL REFERENCES user(id),
    event_id INT NOT NULL REFERENCES event(id),
    status_id INT NOT NULL DEFAULT 1 REFERENCES status(id),
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Создание таблицы «Отзыв»
CREATE TABLE review (
    id SERIAL PRIMARY KEY,
    request_id INT UNIQUE NOT NULL REFERENCES request(id),
    text TEXT NOT NULL,
    rating INT CHECK (rating BETWEEN 1 AND 5),
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

**Задание 6.2.** Выполните скрипт в СУБД (если доступна) и проверьте, что таблицы созданы без ошибок.
