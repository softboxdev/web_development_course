## Этап 2. Анализ требований и ТЗ 

**Результат:** документ «Техническое задание» (или раздел в пояснительной записке).

**Что включить:**
- **Цель и задачи.** Зачем приложение, какие проблемы решает.
- **Функциональные требования.** Что умеет приложение (регистрация, авторизация, CRUD сущностей, поиск, фильтрация, пагинация).
- **Нефункциональные требования.** Производительность (время отклика), безопасность (HTTPS, защита от инъекций), доступность (мобильная версия), масштабируемость.
- **Роли и права доступа.** Что может каждый тип пользователя.
- **Сценарии использования (Use Cases).** Кратко: «Пользователь регистрируется», «Админ удаляет объявление».
- **Ограничения.** Технологии (стек), сроки, бюджет (если есть).

**Совет:** оформите требования в виде таблицы: «Функция — Описание — Приоритет — Статус».

## Этап 3. Проектирование архитектуры и БД 

### Архитектура
Опишите стек и компоненты:
- **Клиент:** браузер, SPA/MPA, фреймворк (React, Vue, Angular) или чистый HTML/CSS/JS.
- **Сервер:** язык и фреймворк (Node.js + Express, Python + Django/FastAPI, Java + Spring, PHP + Laravel).
- **База данных:** реляционная (PostgreSQL, MySQL) или NoSQL (MongoDB) — выбирайте по задаче.
- **API:** REST или GraphQL.
- **Инфраструктура:** локальная разработка, Docker, хостинг (Vercel, Render, Railway, Heroku‑аналоги).

### Проектирование БД
- **Сущности и атрибуты.** Например: `users(id, email, password_hash, role)`, `ads(id, title, description, category_id, user_id, created_at)`.
- **ER‑диаграмма.** Нарисуйте в draw.io, Lucidchart или Miro. Покажите связи (один‑ко‑многим, многие‑ко‑многим).
- **Нормализация.** Приведите до 3‑й нормальной формы (уберите дубли, выделите справочники).
- **Индексы и ограничения.** Укажите, какие поля индексировать (email, title), внешние ключи, NOT NULL, UNIQUE.

**Чек‑лист:**
- [ ] ER‑диаграмма готова.
- [ ] Описаны типы данных и ограничения.
- [ ] Указаны индексы для частых запросов.
- [ ] Продумана миграция (как обновлять схему БД).

## Этап 5. Реализация 

Разбейте на итерации по 1–2 недели:

1. **Настройка проекта и CI/CD.** Git, структура папок, зависимости, переменные окружения.
2. **Серверная часть.** Роуты, контроллеры, сервисы, валидация входных данных.
3. **Работа с БД.** Модели, миграции, seed‑данные (начальные тестовые записи).
4. **API.** Документация (Swagger/OpenAPI) или набор Postman‑коллекций.
5. **Клиентская часть.** Страницы, компоненты, роутинг, состояние.
6. **Авторизация и безопасность.** Регистрация, вход, JWT/сессии, защита роутов, хеширование паролей.
7. **Интеграция клиента и сервера.** Запросы к API, обработка ошибок.
8. **Тестирование.** Юнит‑тесты (минимум для критических функций), интеграционные тесты, E2E (по возможности).

**Примеры стеков:**
- Node.js (Express) + PostgreSQL + React.
- Python (FastAPI) + SQLite/PostgreSQL + Vue.
- Java (Spring Boot) + H2/PostgreSQL + Thymeleaf или React.
- другие.

**Важно:** пишите чистый код, используйте паттерны (MVC/MVVM, Repository), делайте понятные коммиты.

## Этап 6. Тестирование и отладка

**Виды тестов:**
- **Юнит‑тесты:** отдельные функции (валидация, бизнес‑логика).
- **Интеграционные:** API + БД, сценарии с реальными данными.
- **E2E:** сценарии пользователя (зарегистрироваться, создать запись, удалить).

**Метрики для отчёта:**
- Покрытие тестами (если есть инструмент).
- Количество найденных и исправленных багов.
- Время отклика API (среднее/95‑й перцентиль).

**Чек‑лист готовности:**
- [ ] Приложение запускается локально и на сервере.
- [ ] Все функции из ТЗ реализованы.
- [ ] Нет критических уязвимостей (SQL‑инъекции, XSS, CSRF).
- [ ] Есть тестовые данные и сценарии.
