# ЧАСТЬ 1. Шаг 1.4 — Проверка хеширования паролей

## Цель шага

Убедиться, что функция `generate_password_hash()` корректно хеширует пароль, а `check_password_hash()` правильно сравнивает введённый пароль с хешем.

---

## Шаг 1. Создание тестового файла

В **корневой папке проекта** (`~/conference_portal`) создайте файл `test_hash.py`.

### Способ А. Через редактор nano

```bash

```

### Способ Б. Через редактор vim


### Способ В. Через VS Code (если установлен)

```bash

```

---

## Шаг 2. Запись содержимого файла

Вставьте в файл следующий код:

```python
from werkzeug.security import generate_password_hash, check_password_hash

# Хеширование
password = "Demo77"
hashed = generate_password_hash(password, method='pbkdf2:sha256:600000', salt_length=16)
print(f"Пароль: {password}")
print(f"Хеш: {hashed}")
print(f"Длина хеша: {len(hashed)}")

# Проверка
print(f"Верный пароль: {check_password_hash(hashed, 'Demo77')}")
print(f"Неверный пароль: {check_password_hash(hashed, 'wrong')}")
```

**Пояснения по коду:**

| Строка | Что делает |
|--------|------------|
| `import ...` | Импортирует функции хеширования из Werkzeug |
| `password = "Demo77"` | Исходный пароль (как у администратора) |
| `generate_password_hash(...)` | Создаёт хеш с указанным алгоритмом |
| `method='pbkdf2:sha256:600000'` | Алгоритм PBKDF2 + SHA-256 + 600 000 итераций |
| `salt_length=16` | Длина соли — 16 байт |
| `check_password_hash(hashed, ...)` | Сравнивает пароль с хешем |

## Шаг 6. Дополнительные проверки

### 6.1. Уникальность хешей (соль работает)

Хеширование одного и того же пароля **дважды** должно давать **разные** хеши (за счёт случайной соли):

Создайте файл `test_hash_salt.py`:

```python
from werkzeug.security import generate_password_hash

password = "Demo77"

hash1 = generate_password_hash(password, method='pbkdf2:sha256:600000', salt_length=16)
hash2 = generate_password_hash(password, method='pbkdf2:sha256:600000', salt_length=16)

print(f"Хеш 1: {hash1[:60]}...")
print(f"Хеш 2: {hash2[:60]}...")
print(f"Хеши одинаковые? {hash1 == hash2}")
```

**Ожидаемый результат:**
```
Хеши одинаковые? False
```

✅ **Если False** — соль работает правильно: два одинаковых пароля дают разные хеши.

### 6.2. Проверка длины пароля

```python
from werkzeug.security import generate_password_hash

# Очень длинный пароль
long_password = "a" * 1000
hash_long = generate_password_hash(long_password, method='pbkdf2:sha256:600000')
print(f"Длина хеша длинного пароля: {len(hash_long)}")
```

**Ожидаемый результат:** длина остаётся ~102 символа (Werkzeug ограничивает автоматически).

# ЧАСТЬ 2. Шаг 2.5 — Тест на SQL-инъекцию

## Цель шага

Убедиться, что использование **подготовленных выражений** (prepared statements) с параметрами `?` полностью защищает приложение от SQL-инъекций.

---

## Предварительные условия

Для выполнения теста **база данных должна существовать**. Проверьте:

```bash
ls -la database/conference.db
```

**Ожидаемый результат:**
```

```

### Если базы нет

```bash

```

Проверьте таблицы:

```bash
sqlite3 database/conference.db ".tables"
```

**Ожидаемый результат:**
```
event  request  review  status  user
```

---

## Шаг 1. Создание тестового файла

В **корневой папке проекта** (`~/conference_portal`) создайте файл `test_sql_injection.py`.

```bash
nano test_sql_injection.py
```

## Шаг 2. Запись содержимого файла

Вставьте следующий код:

```python
from backend.database import Database

db = Database()

# Попытка SQL-инъекции
malicious_login = "' OR '1'='1"
result = db.fetch_all(
    "SELECT * FROM user WHERE login = ?",
    (malicious_login,)
)
print(f"Результат инъекции: {len(result)} записей")
# Ожидается: 0 записей (инъекция не сработала)
```

**Пояснения по коду:**

| Строка | Что делает |
|--------|------------|
| `from backend.database import Database` | Импортирует Singleton-класс работы с БД |
| `db = Database()` | Создаёт/получает единственный экземпляр подключения |
| `malicious_login = "' OR '1'='1"` | Классическая строка SQL-инъекции |
| `db.fetch_all(...)` | Выполняет безопасный запрос с параметром `?` |
| `print(f"...")` | Выводит количество найденных записей |

### Разбор результата

| Что произошло | Почему |
|---------------|--------|

## Шаг 7. Расширенный тест (несколько видов инъекций)

Создайте файл `test_sql_injection_extended.py`:

```python
from backend.database import Database

db = Database()

# Различные попытки инъекций
attacks = [
    "' OR '1'='1",
    "'; DROP TABLE user; --",
    "admin'--",
    "' UNION SELECT * FROM user --",
    "1' OR '1'='1' /*",
]

print("=" * 60)
print("ТЕСТ ЗАЩИТЫ ОТ SQL-ИНЪЕКЦИЙ")
print("=" * 60)

for attack in attacks:
    result = db.fetch_all(
        "SELECT * FROM user WHERE login = ?",
        (attack,)
    )
    status = "✅ ЗАЩИЩЕНО" if len(result) == 0 else "❌ УЯЗВИМО"
    print(f"{status}: '{attack}' → {len(result)} записей")

# Проверка, что таблица user не удалена
check = db.fetch_all("SELECT name FROM sqlite_master WHERE type='table' AND name='user'")
print("=" * 60)
if check:
    print("✅ Таблица user существует — инъекции не сработали")
else:
    print("❌ Таблица user удалена — инъекция сработала!")
print("=" * 60)
```

**Запустите:**

```bash
python test_sql_injection_extended.py
```

**Ожидаемый результат:**

```
ТЕСТ ЗАЩИТЫ ОТ SQL-ИНЪЕКЦИЙ
============================================================
✅ ЗАЩИЩЕНО: '' OR '1'='1' → 0 записей
✅ ЗАЩИЩЕНО: ''; DROP TABLE user; --' → 0 записей
✅ ЗАЩИЩЕНО: 'admin'--' → 0 записей
✅ ЗАЩИЩЕНО: '' UNION SELECT * FROM user --' → 0 записей

============================================================
```

# ЧАСТЬ 3. Возможные проблемы и решения

## Проблемы при выполнении шага 1.4

| Проблема | Причина | Решение |
|----------|---------|---------|
| `ModuleNotFoundError: No module named 'werkzeug'` | Werkzeug не установлен | `pip install Werkzeug==2.3.7` |
| `ModuleNotFoundError: No module named 'backend'` | Запуск не из корня проекта | `cd ~/conference_portal` |
| `SyntaxError: invalid syntax` | Опечатка в коде | Проверьте отступы и кавычки |

## Проблемы при выполнении шага 2.5

| Проблема | Причина | Решение |
|----------|---------|---------|
| `ModuleNotFoundError: No module named 'backend'` | Запуск не из корня | `cd ~/conference_portal` |
| `sqlite3.OperationalError: no such table: user` | БД не создана | `sqlite3 database/conference.db < schema.sql` |
| `TypeError: fetch_all() missing 1 required positional argument` | Забыли параметры | Передайте `(malicious_login,)` — **с запятой!** |
| `Результат инъекции: 1 записей` | Кто-то реально создал пользователя с логином `' OR '1'='1` | Удалите: `DELETE FROM user WHERE login LIKE '%OR%';` |
| `FileNotFoundError: conference.db` | БД не найдена | Проверьте путь `backend/database.py` |

### Особое внимание: кортеж из одного элемента

**Ошибка:**

```python
db.fetch_all("SELECT ...", (malicious_login))  # ❌ НЕ кортеж, а строка!
```

**Правильно:**

```python
db.fetch_all("SELECT ...", (malicious_login,))  # ✅ Кортеж с запятой
```

> **Правило Python:** для кортежа из одного элемента обязательно нужна **запятая** после значения.
